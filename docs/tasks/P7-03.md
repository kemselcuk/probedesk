## Kabul ölçütleri

- [x] Eşzamanlı iki başlangıç iki aktif run üretemez. — İki ayrı API süreci, 5 tur, gerçek HTTP/DB: her turda `[202, 409]`, DB'de tek RUNNING run, 409 `RUN_ALREADY_ACTIVE` + doğru `activeRunId`. Mevcut tek süreçli `runs.e2e-spec.ts` testi de aynı kısıtı kapsıyor.
- [x] Cancel/final ölçüm yarışında tek terminal durum ve geç yazma koruması vardır. — Mevcut `runs-cancel.e2e-spec.ts`: kontrollü scheduler ile son örnek sınırında cancel/completion yarışı, tek terminal olay, terminal sonrası yazma yok, kısmi ölçüm ve tamamlanan adımlar korunuyor; satır kilidiyle sample/cancel sırası ayrıca doğrulanıyor.
- [x] Zorla kapat/aç sonrası ölçümler korunur; Interrupted readiness öncesi oluşur. — Gerçek `dist/main.js` süreci SIGKILL; ölçüm/olaylar aynı, yeni sürecin ilk başarılı `/health/ready` yanıtında run INTERRUPTED, `SERVER_RESTART`; resume yok.
- [x] Yeni deneme yeni run'dır; eski kısmi kayıt değişmez. — Retry yeni run id'si alıyor; eski run'ın status/recordedSampleCount/finishedAt/eventSequence/ölçüm/olay kümesi retry ilerlerken ve retry cancel edildikten sonra da birebir aynı.
- [x] Kontrollü kapanış RUNNING bırakır; shutdown sonrası COMPLETED commit yok. — Gerçek süreç SIGTERM; run RUNNING, `finishedAt=null`, `run.completed` yok, ölçümler korunuyor; sonraki süreç INTERRUPTED yapıyor.
