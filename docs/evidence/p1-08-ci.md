## Sözleşme işinin dürüstlüğü

`openapi:check`, çalışmadan önce commit edilmiş belgeyi okur, kendi içinde
`openapi:emit` çalıştırır ve byte karşılaştırması yapar. Bu nedenle iş akışında
`openapi:emit` adımından hemen sonra `git diff --exit-code -- apps/api/openapi.json`
çalıştırılır; aksi halde emit'in eski commit edilmiş belgeyi ezmesi drift'i
gizleyebilirdi. `git ls-files --error-unmatch` belgenin izlenen bir dosya
olduğunu doğrular. `continue-on-error`, `|| true` veya koşulsuz başarı adımı
yoktur.

## PostgreSQL servis konteyneri

`api_integration` işi `postgres:18.1-alpine` imajını health check ile başlatır:

- `POSTGRES_DB=probedesk_test`, kullanıcı/parola yalnızca bu geçici konteyner içindir.
- `TEST_DATABASE_URL`, `probedesk_test` veritabanına işaret eder.
- `DATABASE_URL`, aynı sunucuda ayrı bir kimlik olan `probedesk_dev` veritabanına
  işaret eder. Test veritabanı koruması (`requireTestDatabaseUrl`) geliştirme ve
  test URL'lerinin aynı veritabanını göstermesini reddettiği için bu ayrım
  zorunludur. Mevcut işler `probedesk_dev` veritabanına bağlanmaz; değer yalnızca
  güvenlik korumasını tatmin eden CI sentinel'idir.
- Konteyner volume kullanmaz; iş bitince veri kaybolur.

Repository secret'ı, token, cookie veya kalıcı parola kullanılmaz. Bu nedenle
fork pull-request'leri için ek secret politikası gerekmez.

### Eşzamanlı auth çalışması sırasındaki yerel sonuç

14:45-14:48 arasındaki ilk turda API unit 2 dosya/15 test, web unit 7 dosya/17
test ve API e2e 5 dosya/24 test geçti; `openapi:check` de geçti. Bu sırada auth
görevi `apps/api` ve `apps/web` üzerinde değişiklik yapmaya devam ediyordu.

14:50'de CI ortamına benzer `DATABASE_URL`/`TEST_DATABASE_URL` değerleriyle
yapılan tekrar çalıştırmada yeni auth migration'ı test veritabanına uygulandı,
ancak e2e iki dosyada başarısız oldu:

- `test/auth.e2e-spec.ts`: `SessionAuthGuard` için `AuthService` çözülemedi;
  auth testleri atlandı ve temizlik hook'u hata verdi.
- `test/openapi.e2e-spec.ts`: güvenlik şeması sırası beklenenden farklı ve
  commit edilmiş `apps/api/openapi.json` yeni auth rotalarını içermiyor.

Bu nedenle mevcut ağaçta `api_integration` ve `contract` işlerinin kırmızı
olması beklenir. Auth çalışması tamamlanıp OpenAPI belgesi ve istemci tipleri
yeniden üretildikten sonra bu komutlar tekrar çalıştırılmalıdır. Bu, iş
akışının hatası değil, gerçek drift/eksik entegrasyonun görünür olmasıdır.

`openapi:check` kendi içinde emit edip commit edilmiş belgeyle karşılaştırdığı
için üst düzey `npm run openapi:emit` ayrıca çalıştırılmadı; ilk turda kontrolün
geçmesi emit çıktısının o anda commit edilmiş dosyayla aynı olduğunu gösterir.
İş akışındaki `git diff --exit-code` adımı yerelde çalıştırılmadı (git işlemleri
lead'e ait); gerçek koşuda doğrulanacak.

Web unit testleri geçmesine rağmen jsdom ortamında `el.scrollTo is not a function`
şeklinde tekrarlanan `stderr` çıktısı üretti. Bu çıktı testleri düşürmüyor; ayrı
bir UI testi temizliği olarak izlenmeli, CI başarısızlığı olarak sayılmadı. Web
lint'te auth dosyasında bir uyarı, web build'de 500 kB uyarı bütçesi aşımı var;
ikisi de çıkış kodunu 0 tutuyor.

## Bekleyen kabul adımları

1. Lead commit/push sonrası gerçek GitHub Actions koşusunun bağlantısını ve
   sonucunu kaydetmek.
2. Kontrollü bir başarısız kontrol gösterimi yapmak (örneğin geçici bir hatalı
   commit/PR ile bir işi düşürmek) ve `CI required` işinin de düştüğünü
   doğrulamak.
3. API ve web işlerinin Actions arayüzünde ayrı ayrı göründüğünü gerçek koşuyla
   doğrulamak.
4. Gerçek koşuda servis konteyneri health check'inin, `npm ci` süresinin ve
   artifact davranışının beklendiği gibi çalıştığını kaydetmek.

Bu adımlar tamamlanmadan P1-08 `Accepted` yapılmaz.
